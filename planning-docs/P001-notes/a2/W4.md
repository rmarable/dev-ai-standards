# W4 notes: bin/new-claude-project

## Files
- `bin/new-claude-project`: the one-command launcher (P001 "One-command launch", "Who may run what").
  Preflight, choices, local build via `bin/dev-ai-standards apply`, M1 stub, one y/N, `gh repo create`,
  ruleset when allowed, opens `claude`.
- `tests/test_new_claude_project.py`: 12 stdlib unittest tests. Fake `gh`/`claude` first on PATH;
  kit copied to a temp dir with a local bare upstream (no network, never pulls the real kit). Uses
  the real `bin/dev-ai-standards` when present (then also asserts `drift` exits 0), else a fake;
  `NCP_TEST_FAKE_APPLY=1` forces the fake. Interactive paths run in a pty.
  Result: `python3 -m unittest discover -s out/tests -p 'test_new_claude_project.py'`: 12 run, OK
  (fake apply; the real one wasn't in `out/` yet).

## Choices the spec didn't settle
- Claude detection: `CLAUDECODE` set, or stdin or stdout not a TTY. The refusal (exit 2) comes first,
  before any preflight, so a refused run touches nothing.
- Env knobs: `NEW_CLAUDE_PROJECT_OWNER` (default `rmarable`), `NEW_CLAUDE_PROJECT_ROOT` (default
  `~/src`, used by tests), `NEW_CLAUDE_PROJECT_GH_PLAN` (default `free`; any other value makes a
  private run try the ruleset, which is how A4 tries it once), `DEV_AI_STANDARDS_BIN` (apply override).
- `--local` skips every `gh` call (auth and name check), and skips the kit pull only when the kit has
  no upstream (as the plan says). Without `--local`, a kit with no upstream stops the run.
- `--dry-run` runs the read-only checks (git config, folder, `gh auth status`, `gh repo view`), does
  not pull the kit, and doesn't call `apply` (the target doesn't exist); it prints each action.
- Name check: `gh repo view` exit 0 = taken; non-zero with "Could not resolve to a Repository" =
  free; any other error stops ("can't check").
- Missing choices are asked only with a human; Claude-run `--local`/`--dry-run` use the defaults and
  print them. Without `--high-stakes`/`--codex` a human is asked (no `--core`/`--no-codex` flags).
- Commit timing: under `--local` the first commit happens without a prompt (caller's approval); for
  remote runs the commit comes after the y/N, so a "No" leaves an uncommitted build, reported.
- First commit message: `new-claude-project: initial commit`, blank line, then the one Claude trailer.
- `--public`: secret scan of the untracked, non-ignored files (AWS key id, private key block, GitHub,
  Slack, Anthropic, OpenAI-style keys; prints file:line and kind only), then the name typed back,
  then the y/N. `--public --local` is an error.
- Rulesets: two, via `gh api --method POST repos/<owner>/<name>/rulesets --input -`: `main` (deletion,
  non_fast_forward; unless `--no-pr`: pull_request with 0 approvals and `allowed_merge_methods:
  ["merge"]`, required_status_checks `rules-check`, plus `local-gate` and strict up-to-date when
  high-stakes) and `release tags` on `refs/tags/v*` (deletion, non_fast_forward). Payload shape and
  `allowed_merge_methods`: unproven until A4. Context names `rules-check` and `local-gate` must match
  the job name in `templates/ci/rules-check.yml` and the context `bin/gate-status` posts (other
  drafters; reconcile at review).
- 0 required approvals: a solo new project; team repos need one human approval (high-stakes
  "Approvers") and must raise it themselves.
- M1 stub at `planning-docs/milestones/M1-<name>.md`, planning header (`Owner: operator`) and tail
  sections; kept untouched if `apply` already wrote that file.
- Launch: `os.execvp("claude", [prompt])` in the project folder. Without a TTY Claude isn't opened;
  next steps are printed instead. `--codex` prints `git -C <dir> worktree add -b codex/<topic>
  ../<name>-codex-<topic> origin/main` (`main` under `--local`).
- Failure: one-line reason on stderr, then a list of what exists; nothing deleted. A failed
  `gh repo create` re-checks with `gh repo view` and lists the repo if it exists.
